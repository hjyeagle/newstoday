🗂 8GB 메모리를 사용하는데 32GB의 데이터를 분석해서 제출하라는 채용과제를 받았다면?! 📝

  • 문제 상황 정의: 개인 노트북(8~32GB RAM) 환경에서 30GB 이상의 대용량 파일이나 채용과제를 처리해야 하는 현실적인 한계 상황 해결법을 다룹니다.
  • 환경 최적화 사전 작업: 불필요한 주피터 노트북 셧다운, 컴퓨터 재부팅, 가상 메모리 및 그래픽 설정 조정을 통해 기본 메모리 리소스를 확보합니다.
  • 청크(Chunk) 단위 로딩: pd.read_csv()의 chunksize 매개변수를 활용해 대용량 파일 전체를 한 번에 올리지 않고 100만 건씩 쪼개어 반복 처리합니다.
  • 데이터 타입 다운캐스팅: int64, float64를 int8, int32, category 등으로 줄여 데이터 변경만으로 메모리 점유율을 70~80% 이상 획기적으로 낮춥니다.
  • 파케이(Parquet) 포맷 변환: 열(Column) 기반 압축 및 메타데이터를 저장하는 파케이 포맷을 적용하여 디스크 용량과 파일 입출력 속도를 대폭 개선합니다.
  • 서브셋(Subset) 추출 및 경량화: 리텐션 분석 등 특정 목적에 필요한 핵심 컬럼과 조건 행만 추출하여 파일 크기를 최적화합니다.
  • 대용량 데이터 처리 라이브러리: 다스크(Dask), 벡스(Vaex), 파이스파크(PySpark) 및 멀티프로세싱 모듈을 활용하는 분산/병렬 처리 방안을 소개합니다.

분석하기 좋은 데이터는 어떤 데이터 일까요?

  • 타이디 데이터(Tidy Data) 정의: 뉴질랜드 통계학자 해들리 위컴(Hadley Wickham)이 정의한 개념으로, "각 변수는 열(Column)이 되고 각 관측치는 행(Row)이 되는 데이터" 구조입니다.
  • 지저분한 데이터의 예시: 연도/월이나 소득 구간별 수치가 여러 열로 펼쳐져 있어 통계 처리나 시각화에 적합하지 않은 형태입니다.
  • 판다스 melt() 기능: 열에 위치한 변수 데이터를 행으로 녹여내는 pd.melt() 함수를 통해 언피벗(Unpivot)하여 타이디 데이터 구조로 변환합니다.
  • 공공데이터 전처리 적용: 신규 민간아파트 평당 분양가격 공공데이터의 연도, 월, 가격 컬럼을 멜트(Melt)하여 분석 및 시각화용 데이터로 재구조화했습니다.
  • 씨본(Seaborn)과의 연계성: 씨본 라이브러리는 입력 데이터가 '타이디 데이터' 형태임을 전제로 설계되어 있어, 구조가 정돈되면 코드 한 줄로 쉽게 시각화할 수 있습니다.
  • 데이터 분석의 기본 조건: 차트 작성 및 모델링 전 데이터를 깔끔한 테이블 구조로 변환하는 전처리 작업이 필수적임을 강조합니다.
