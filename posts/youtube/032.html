선택하신 17개 영상에 대한 구체적인 요약본입니다. 각 영상 제목을 그대로 챕터명으로 지정하여 6~7개 항목으로 구체적으로 정리하였으며, 마지막에 '라벨 종합 정리'를 작성했습니다.

노코드툴 앱시트 AI 기능 출시! (앱 제작에 유용할까?)

  • Start with Gemini 기능 소개: 앱시트 상단 Create 메뉴에서 Gemini 프롬프트 입력을 통해 초기 앱 스키마를 자동 생성하는 익스페리멘탈 AI 기능입니다.
  • 프롬프트 상세도 및 언어별 테스트: 한글/영문, 간단한 요청/상세한 요청 등 4가지 프롬프트 입력 방식을 비교 테스트하여 스키마 파악 및 테스트 데이터 생성 양상을 확인합니다.
  • 자동 생성 범위의 한계: 프롬프트 기반으로 테이블 구조, 컬럼명, 테스팅 샘플 데이터까지만 일차적으로 잡아주며, 뷰(View) 디자인, 액션(Action), 봇(Bot), 포맷 룰 등은 자동 생성되지 않습니다.
  • 영문 프롬프트의 상대적 우수성: 한글 프롬프트로도 스키마 생성이 가능하나, 영문으로 작성할 때 컬럼명 매핑과 가상 테스팅 데이터(과일명이 아닌 실제 IT 제품명 등)가 더 정교하게 들어갑니다.
  • 초보자 가이드용 활용성: DB 구조 생성과 소스 연결 흐름을 파악하는 초보자 학습용으로 유용하지만, 복잡한 실무 앱 제작 생산성을 획기적으로 끌어올리기에는 아직 초기 단계입니다.
  • 실무 권장사항: 현시점 제미나이 AI 기능은 앱시트 데이터베이스(AppSheet Database)를 기본 소스로 생성하므로, 실제 실무 앱 제작 시에는 기존 구글 스프레드시트 기반 제작을 우선 추천합니다.

노코드툴 앱시트로 나만의 가계부 만들기(중급자용) - 파트1

  • 가계부 앱 소스 테이블 5가지 설계: budget(예산), transaction(거래내역), calendar(일정), category(분류), filter(대시보드 검색) 5개 테이블 소스를 연결하여 개발을 시작합니다.
  • 날짜 관련 수식 및 가상 컬럼 구축: Year(TODAY()), Month(TODAY()) 수식으로 숫자를 추출하고, CONCATENATE([Year], "-", [Month]) 수식으로 year_month 가상 컬럼을 조합합니다.
  • 레퍼런스(Ref) 연결과 가상 컬럼: budget과 category 테이블을 Ref 타입으로 연결한 후 [category_id].[name] 형태로 카테고리 이름을 직관적으로 가져오는 가상 컬럼을 추가합니다.
  • 식별 용이성을 위한 커스텀 키 설정: 유니크 아이디(UNIQUEID()) 대신 연도, 월, 카테고리명을 결합한 CONCATENATE([year_month], "-", [category_name]) 구조로 직관적 키값을 생성합니다.
  • filter 테이블 및 Enum/EnumList 세팅: 대시보드 다차원 검색을 위한 filter 테이블을 구성하고 검색 유저 이메일(USEREMAIL()), 지불 수단, 연도/월 선택 EnumList를 세팅합니다.
  • 디스플레이 네임 한글화: 각 컬럼의 Display Name을 한글로 커스텀 설정하여 유저가 앱 입력 폼에서 깔끔한 UI로 작업할 수 있도록 기반을 조성합니다.

노코드툴 앱시트로 나만의 가계부 만들기(중급자용) - 파트3

  • 대시보드 필터용 슬라이스(Slice) 제작: transaction 테이블에서 filter 테이블의 조건(결제 방식, 수입/지출, 카테고리, 연도, 월)에 부합하는 데이터만 동적으로 걸러내는 슬라이스를 생성합니다.
  • AND / OR 복합 필터 수식 구성: filter[boolean] 컬럼값(AND/OR)을 판별하여 AND() 또는 OR() 구문으로 여러 동적 필터 조건을 교집합/합집합으로 제어합니다.
  • Multi-user 보안 필터(Security Filter): 다수의 유저가 동시 접속 시 필터 설정값이 덮어씌워지는 문제를 방지하기 위해 [email] = USEREMAIL() 보안 필터를 적용합니다.
  • 신규 차트 뷰(Preview New Features) 구현: 월별 지출/수입 추이를 보여주는 바 차트(Bar Chart)와 카테고리/결제 형태 비중을 보여주는 도넛 차트(Donut Chart)를 대시보드 뷰로 배치합니다.
  • Suggested Values 조건부 드롭다운: 거래 내역 입력 폼에서 수입/지출 선택에 따라 상응하는 카테고리만 드롭다운에 노출되도록 SELECT(category[category_id], [expense_type] = [_THISROW].[expense_type]) 수식을 적용합니다.
  • 필터 초기화(Clear) 액션 제작: 선택된 필터 검색 조건값들을 빈칸으로 되돌려주는 클리어 액션 버튼을 생성하여 대시보드 사용성을 높입니다.

노코드툴 앱시트로 나만의 가계부 만들기(중급자용) - 파트4

  • 거래 내역 등록 시 캘린더 자동 이관 액션: transaction 테이블에 새로운 데이터가 추가되면 Add a new row to another table 액션을 발동시켜 calendar 테이블에도 데이터를 자동 생성합니다.
  • LOOKUP 수식을 활용한 캘린더 업데이트 봇(Bot): transaction 데이터 수정 시 calendar 테이블도 동기화되도록 LOOKUP([transaction_id], "transaction", "transaction_id", "amount") 수식 기반 봇을 구축합니다.
  • 예산 소진 임박 이메일 알림 봇: [budget_left] / [amount] <= 0.1 조건을 충족할 때 잔여 예산 10% 이하 알림 메일을 유저 이메일(USEREMAIL())로 자동 발송합니다.
  • 이메일 템플릿 커스터마이징: 브라켓 연동 구문(<<[category]>>, <<[budget_left]>>)을 활용해 이메일 본문에 남은 예산액과 카테고리 정보를 가독성 높게 구성합니다.
  • 카테고리별 캘린더 색상 구분: 캘린더 뷰에서 수입과 지출 유형별로 색상이 다르게 구분되어 시각적으로 지출 현황을 파악하도록 셋팅합니다.
  • 앱 최종 테스트 및 세부 UI 정돈: 가계부 앱의 수입/지출 등록, 예산 자동 차감, 캘린더 동기화, 대시보드 필터링, 이메일 알림 작동을 종합 검증하고 세부 뷰 레이아웃을 완성합니다.

노코드툴 앱시트로 프로젝트 관리 시스템 만들기(중급자용) - 파트2

  • 대시보드 뷰 기반 프로젝트 메인 구현: 대시보드(Dashboard) 뷰 타입을 활용해 상단 프로젝트 목록 테이블과 하단 상세 디테일 뷰를 한 화면에서 보게 구성하고 Interactive Mode를 활성화합니다.
  • 업무 추가 폼(Form) 뷰 생성: 과업을 신속하게 추가할 수 있도록 primary navigation 위치에 폼 뷰를 배치하고 입력 완료 후 현황판으로 연결되는 Finish View를 세팅합니다.
  • 슬라이스(Slice) 기반 칸반보드(Kanban) 구현: 과업 상태(시작 전, 진행 중, 완료)별로 슬라이스를 3개 생성하고, 이를 카드 뷰(Card View) 형태로 대시보드에 배치하여 칸반보드 현황판을 완성합니다.
  • 가상 컬럼 및 IFS 수식을 활용한 카드 색상 매핑: 과업 유형(기획, 대본, 촬영, 편집 등)에 따라 지정된 로컬 이미지 파일 경로를 IFS() 수식으로 불러와 칸반 카드 상단에 색상으로 표시합니다.
  • 팀원 인명록(My Team) 카드 뷰 구축: 팀별로 직원을 그룹핑하고 사진, 이름, 팀 정보, 전화/이메일 액션 버튼이 포함된 인명록 뷰를 제작합니다.
  • 인터랙티브 캘린더 대시보드 제작: 완료되지 않은 과업만 필터링한 다가오는 일정 뷰와 캘린더 뷰를 결합하여 일정을 한눈에 파악하는 캘린더 대시보드를 구성합니다.

노코드툴 앱시트로 프로젝트 관리 시스템 만들기(중급자용) - 파트3

  • 과업 진행 상태 변경 액션 버튼: 시작 전 -> 진행 중, 진행 중 -> 완료 등으로 과업 상태를 원클릭 변경하고 완료 시 오늘 날짜(TODAY())를 자동 기록하는 액션 버튼을 제작합니다.
  • LINKTOFORM 수식을 활용한 메모 추가 액션: 특정 과업 디테일 화면에서 LINKTOFORM("note_form", "task_id", [_THISROW].[task_id]) 수식을 통해 해당 과업과 연결된 메모 작성 폼으로 즉시 이동시킵니다.
  • Grouped Action을 통한 다중 액션 묶음: 과업 추가 시 시작 일정, 마감 일정, 완료 일정을 calendar 테이블에 각각 행으로 생성하는 3개 액션을 하나로 묶어(Grouped) 폼 세이브 이벤트에 결합합니다.
  • 상태 동기화 봇(Bot) 구축: task 테이블의 status가 변경되면 [_THISROW_BEFORE].[status] <> [_THISROW_AFTER].[status] 조건을 감지해 calendar 테이블의 상태 컬럼도 일괄 업데이트합니다.
  • 일정 변경 시 삭제 후 재생성 봇 구축: 시작/마감/완료 일자가 수정되면 기존 calendar 행들을 먼저 삭제(delete_schedule)한 후 수정된 날짜로 3개 행을 다시 생성하는 워크플로우 봇을 완성합니다.
  • 관련 메모 및 일정 인라인 뷰 정돈: 과업 상세 화면 하단에 연결된 관련 메모(Related Notes)와 관련 일정(Related Calendars)의 컬럼 순서 및 레이아웃을 최신순 내림차순으로 정돈합니다.

앱시트 데이터 엑셀, csv로 추출하기, 이 영상 하나면 끝!

  • Export to CSV 액션을 통한 초간단 추출: Export this View to a csv file 액션 하나로 현재 화면에 필터링된 행 데이터 전체를 CSV 파일로 즉시 다운로드합니다.
  • CSV 내보내기의 제약사항: 레퍼런스(Ref) 타입 컬럼은 추출 시 값이 비어있으므로, 텍스트 타입의 가상 컬럼을 추가해 불러와야 정상 출력됩니다.
  • 구글 드라이브 기반 엑셀(.xlsx) 내보내기 구조: 봇(Bot)과 구글 스프레드시트 템플릿을 연동하여 엑셀 형식의 보고서를 자동 생성하고 구글 드라이브 지정 폴더에 저장합니다.
  • 유저별 필터 폼 및 세큐리티 필터 구축: 유저별로 단일 행만 접근 가능하도록 [user_email] = USEREMAIL() 보안 필터가 적용된 필터 폼을 만들어 검색 날짜 범위를 동적 지정합니다.
  • 템플릿 내 SELECT 수식 기반 필터링 매핑: 엑셀 템플릿 내부 구문에서 <<Start: SELECT(slice_revenue_log[revenue_id], TRUE)>> 수식을 적용해 슬라이스된 범위 데이터만 엑셀 표로 출력합니다.
  • 구글 드라이브 파일 뷰 연동: 생성된 PDF 및 엑셀 파일들을 앱시트 앱 화면 내 카드 뷰로 리스트업하고 Open File 액션 버튼을 통해 유저가 앱 내에서 파일을 즉시 열람·다운로드하게 구현합니다.

앱시트 데이터베이스 vs 스프레드시트 vs RDBMS: 어떤 소스가 제일 좋을까?

  • 앱시트 데이터베이스(AppSheet Database)의 포지셔닝: 구글이 제작한 자체 관계형 DB로 스프레드시트 형태의 직관적 UI와 관계형 DB의 퍼포먼스를 결합한 전용 데이터 관리 시스템입니다.
  • 구글 스프레드시트의 장단점: 사용법이 익숙하고 무료이며 협업이 용이하지만, 데이터가 3만~5만 행 이상 축적되면 속도가 느려지고 데이터 정합성/보안이 상대적으로 약합니다.
  • 앱시트 데이터베이스의 장단점: 대용량 행 처리 및 싱크 퍼포먼스는 스프레드시트보다 우수하지만, 플랜별 행 리밋(무료 1,000행, 코어 2,500행 등)이 엄격하고 타 외부 서비스와의 연동성이 떨어집니다.
  • RDBMS(PostgreSQL/MySQL 등)의 장단점: 무제한 용량 확장성과 외부 시스템 연동성이 뛰어나지만, 엔터프라이즈 플랜 결제 필요 및 전담 관리 인력과 클라우드 운영 비용이 발생합니다.
  • 사용자 상황별 데이터 소스 추천: 일반 비개발자 및 소규모 팀은 가성비와 유연성이 뛰어난 구글 스프레드시트로 시작하는 것이 가장 권장됩니다.
  • 대용량 운영 전략: 데이터 축적량이 많아질 경우 아카이빙 시트와 상시 운용 시트를 분리하거나, 향후 업그레이드될 앱시트 DB 및 엔터프라이즈 RDBMS로의 전환을 고려합니다.

  • 앱시트 싱크(Sync) 작동 구조: 기기(앱)와 데이터 소스 사이에 앱시트 서버가 중간 대행 역할을 수행하여 보안과 처리 속도를 향상시키는 프로세스입니다.
  • 클라우드 퍼포먼스 3대 옵션: 대용량 변경 적은 테이블용 'Server Caching', 변경된 행만 가져오는 'Delta Sync', 동시 편집 유저 간 실시간 반사이익을 주는 'Quick Sync'가 제공됩니다.
  • 동시 다발적 협업용 앱 최적화 조합: Server Caching과 Delta Sync는 끄고, Quick Sync, Sync on Start, Delayed Sync, Automatic Updates 4가지를 켜서 반응 속도와 작업 연속성을 확보합니다.
  • 대용량 속도 최우선 앱 최적화 조합: Server Caching과 Delta Sync를 켜고, Quick Sync와 Sync on Start는 꺼서 앱 가동 및 데이터 로딩 부하를 대폭 줄입니다.
  • 온/오프라인 혼용 앱 최적화 조합: Server Caching, Delayed Sync, Offline Mode를 활성화하여 오프라인에서 작업을 큐(Queue)로 쌓아두었다가 온라인 접속 시 매뉴얼 싱크로 일괄 업데이트합니다.
  • 스프레드시트 수정 시 자동 싱크 부가기능: 'AppSheet Events' 구글 시트 애드온과 오토메이션 봇을 연동해 시트 원본 직접 수정 시에도 앱에 실시간 오토 싱크가 반영되도록 구현합니다.

앱시트 초보자라면 꼭 알아야할 데이터 자동 완성하는 3가지 방법

  • 레퍼런스(Ref) 타입을 활용한 다중 컬럼 자동 완성: Ref 타입으로 타 테이블의 키값을 연결한 뒤, 이니셜 밸류에 [product_id].[category] 형태의 점(Dot) 연산자로 관련 컬럼값들을 한 번에 불러옵니다.
  • LOOKUP 수식을 활용한 단일 컬럼 자동 완성: 레퍼런스 연결 없이 키값 대조만으로 단일 컬럼값을 가져올 때 LOOKUP([sales_email], "employee", "email", "name") 수식을 이니셜 밸류에 설정합니다.
  • 오토메이션 봇(Bot)을 활용한 동적 수정 반영 자동 완성: 이니셜 밸류와 달리 유저가 폼 입력 후 거래 날짜를 나중에 수정하더라도 판매 확정 일자가 14일 자동 재계산되도록 봇 이벤트를 구성합니다.
  • 포뮬러(Formula)와 이니셜 밸류(Initial Value)의 차이: 포뮬러는 유저가 수동 수정할 수 없는 고정 계산인 반면, 이니셜 밸류나 봇 연동 방식은 자동 계산값을 제공하면서도 유저의 수동 수정을 허용합니다.
  • 상황별 자동 완성 선택 가이드: 여러 컬럼 연동 시 Ref 타입, 단일 컬럼 연동 시 LOOKUP, 유저 수동 수정 및 수정 트리거 반영 시 오토메이션 봇을 선택합니다.
  • 자동 완성 기능의 생산성 가치: 반복 기입 및 입력 오류를 대폭 줄여주어 유저의 앱 사용 만족도를 가장 크게 높여주는 필수 기술입니다.

앱시트 초보자라면, 가장 먼저 배워야하는 수식 3가지!

  • Ref 키 컬럼 점(Dot) 연산자: Ref 데이터 타입이 설정된 경우 [transaction_id].[amount]처럼 점을 찍어 상위/연관 테이블의 특정 컬럼값을 가져오는 가장 효율적인 수식입니다.
  • 다단계 점 연산자 확장: [calendar_id].[transaction_id].[category_id].[name]처럼 점 연산자를 다단계로 이어서 수개 테이블을 넘나들며 원하는 컬럼값을 추출할 수 있습니다.
  • LOOKUP 수식 활용법: LOOKUP([match_value], "target_table", "target_key_column", "return_column") 구조로 Ref 연결이 없는 상황에서 단일 키 대조를 통해 원하는 특정 행의 값을 반환합니다.
  • SELECT 수식 활용법: SELECT(transaction[amount], [category] = "식비", TRUE) 구문으로 조건에 맞는 여러 행의 데이터들을 리스트 형태로 가져옵니다.
  • DISTINCT 및 INDEX 수식 결합: SELECT 수식에 TRUE 파라미터를 넣어 중복값을 제거(DISTINCT)하고, INDEX(..., 1) 수식으로 리스트의 특정 순번 값만 잘라내어 활용합니다.
  • 수식 선택 우선순위: 연산 속도와 효율성 측면에서 1순위 Ref 점 연산자 -> 2순위 LOOKUP -> 3순위 SELECT 순으로 적용하는 것이 앱 성능 유지에 유리합니다.

앱시트 테이블 키 값 설정, 아무 생각 없이 하면 후회합니다

  • 키(Key)와 레이블(Label)의 개념: 키는 각 행을 유일하게 구분하는 꼬리표(주소)이며, 레이블은 유저에게 시각적으로 보여주는 대표 명칭(이름)입니다.
  • 키값 설정의 비즈니스적 중요성: 테이블 간 Ref 연동, 데이터 조회, 오토메이션 봇 실행 시 정확한 대상 행을 식별하기 위해 중복 없는 단 하나의 키 조성이 필수적입니다.
  • 방식 1 - UNIQUEID() 생성 (자주 추가되는 로데이터): 거래 내역, 주문서처럼 대표 컬럼이 없고 데이터가 빈번히 쌓이는 경우 이니셜 밸류에 UNIQUEID() 수식을 넣어 8자리 랜덤 키를 부여합니다.
  • 방식 2 - 대표 컬럼 및 혼합키(Composite Key): 이메일, 모델명처럼 유니크한 대표값이 있거나 CONCATENATE([year_month], "-", [category])처럼 여러 컬럼을 결합해 의미 있는 키를 만듭니다.
  • 방식 3 - MAX 수식 기반 순차적 넘버링 키: 프로젝트 ID처럼 순서가 중요한 경우, 가상 컬럼으로 숫자 파트를 추출한 뒤 MAX(table[num_part]) + 1 수식을 적용해 중복 없는 순차 키(ID-003)를 부여합니다.
  • 키값 설정 시 주의사항: 키 생성 수식은 Data 수정 시 키가 바뀌는 부작용을 막기 위해 Formula 란이 아닌 Initial Value 란에 세팅해야 합니다.

앱시트에 홈화면 만드는 꿀팁 공개!

  • 홈 화면 전용 데이터 소스(App Menu) 구성: display_name, link_name, sub_header, icon, display_order, screen, team 컬럼을 가진 전용 메뉴 시트를 연결합니다.
  • 카드 뷰(Card View) 기반 메뉴 배치: 홈 화면 뷰의 타입을 카드 뷰(List 레이아웃)로 지정하고 display_order 오름차순으로 정렬해 깔끔한 버튼 UI를 구현합니다.
  • 슬라이스(Slice)를 활용한 팀별 커스텀 메뉴: 유저의 팀/부서 정보(USEREMAIL())와 슬라이스 필터 조건을 결합해 로그인 유저별로 다르게 노출되는 커스텀 홈 화면을 제작합니다.
  • 다양한 형태의 폼/뷰 연결 액션 버튼: LINKTOFORM() 수식을 통해 프로젝트 추가, 업무 추가, 팀원 추가 폼 뷰로 직접 이동하는 액션들을 제작합니다.
  • 외부 웹사이트 링크 액션 연동: External: go to a website 옵션을 선택해 참고 자료 버튼 클릭 시 지정된 외부 URL(네이버, 사내 위키 등)로 세 창 이동시킵니다.
  • Grouped Action과 Behavior 조건 결합: 4개 이동 액션을 하나의 그룹 액션으로 묶어 홈 카드 뷰 온클릭 이벤트에 할당하고, 각 액션의 Behavior에 [link_name] = "프로젝트 추가" 조건식을 걸어 개별 작동하게 제어합니다.
  • 스타팅 뷰(Starting View) 세팅: Settings -> General -> Starting View 옵션을 홈 뷰(app_menu)로 지정하여 앱 실행 시 항상 첫 화면으로 홈이 떠오르도록 설정합니다.

앱시트에서 드롭다운 메뉴는 이렇게 만드시면 됩니다

  • 드롭다운 생성 3가지 데이터 타입: Ref 타입(타 테이블 키 연동), Enum / EnumList 타입(단일/복수 선택 전용), Text 타입 + Suggested Values 조합 방식이 제공됩니다.
  • 목록 수정 제어 기법: Ref 타입은 원본 테이블 세팅의 Add 권한 해제, Enum 타입은 Allow other values 해제, Text 타입은 Data Validity에 허용 리스트 포뮬러를 적용해 수동 추가를 차단합니다.
  • Suggested Values 동적 목록 구성: suggested_values 란에 SORT(table[column], TRUE) 수식을 작성하여 유저가 새로 입력한 데이터도 드롭다운 목록에 동적으로 정렬·추가되게 세팅합니다.
  • ORDERBY 수식을 통한 키값 정렬: ORDERBY(task[task_id], [start_date], TRUE) 구문으로 정렬 기준 컬럼(시작 일자 등)을 지정해 드롭다운 순서를 컨트롤합니다.
  • 드롭다운 목록 연동(Dependent Dropdown): 상위 컬럼(프로젝트 ID) 선택에 따라 하위 컬럼(과업 ID) 목록이 동적으로 달라지도록 SELECT(task[task_name], [project_id] = [_THISROW].[project_id]) 수식을 적용합니다.
  • 상황별 타입 선택 기준: 다른 컬럼 참조 필요 시 Ref 타입, 정적 목록은 Enum, 자유로운 입력과 동적 제어가 동시에 필요할 땐 Text + Suggested Values 조합을 선택합니다.

앱시트에서 인터렉티브한 앱을 만들기 위한 필수 수식 총정리

  • 동적 조건 수식 IF / IFS: 조건 1개일 땐 IF(cond, true_val, false_val), 조건 다수일 땐 IFS(cond1, val1, cond2, val2, TRUE, default_val) 구문을 사용하며, 마지막에 TRUE 조건을 배치해 디폴트값을 처리합니다.
  • 조건 조합 수식 AND / OR: AND(cond1, cond2)는 모든 조건 충족 시 True, OR(cond1, cond2)는 하나라도 충족 시 True를 반환하며 슬라이스, Show_if, 봇 조건에 활용됩니다.
  • 참/거짓 검증 수식 IN / CONTAINS: IN(USEREMAIL(), employee[email])은 리스트 내 존재 여부를, CONTAINS([description], "검색어")는 텍스트 문단 내 특정 문자열 포함 여부를 판별합니다.
  • 공백 검증 수식 ISBLANK / ISNOTBLANK: ISBLANK([date]) 및 ISNOTBLANK([date]) 수식으로 컬럼의 입력 여부를 검증하여 액션 실행 여부(Behavior)나 뷰 노출 조건(Show_if)을 제어합니다.
  • NOT 수식을 통한 참/거짓 반전: NOT(ISBLANK([date]))처럼 수식 결과값을 반대로 뒤집어 조건 논리를 손쉽게 전환합니다.
  • 인터랙티브 UI 반응성 강화: 이니셜 밸류, Show_if, Behavior, 슬라이스 조건에 조건 수식들을 조합함으로써 유저의 입력에 따라 앱 UI가 실시간으로 가변 반응하도록 만듭니다.

앱시트에서 텍스트를 자유 자재로 활용하기 위한 필수 수식 총정리

  • 텍스트 결합 수식 CONCATENATE: CONCATENATE([year], "-", [month], "-", [category]) 구문으로 여러 컬럼과 문자열을 결합해 혼합키, 가상 컬럼, 동적 URL을 만듭니다.
  • 텍스트 분동 및 선택 수식 SPLIT / INDEX: SPLIT([text], "@") 수식으로 텍스트를 구분자 기준 리스트로 쪼갠 후, INDEX(..., 2) 수식을 결합해 특정 순번의 문자열(도메인 등)만 잘라냅니다.
  • 구분자 기반 액션 분기 처리: 콤마로 연결된 텍스트 데이터를 SPLIT과 INDEX 수식으로 분리하여 다른 테이블에 각 파트별로 개별 행을 추가하는 자동화 액션을 구현합니다.
  • 텍스트 자르기 수식 RIGHT / LEFT: RIGHT([url], 11) 구문으로 유튜브 URL의 우측 11자리를 잘라내어 비디오 ID만 정밀 추출합니다.
  • 길이 및 위치 검색 수식 LEN / FIND: LEN([text])로 전체 길이를 구하고 FIND("?", [url])로 특정 문자 위치를 찾아 가변적 길이의 문자열을 다이내믹하게 잘라냅니다.
  • 복합 텍스트 가공 기술: SPLIT, INDEX, RIGHT, LEN, FIND 수식을 조합함으로써 가변적인 외부 URL이나 비표준 규격 문자열 데이터에서 원하는 텍스트 파트만 완벽히 정제합니다.

직원 온보딩을 앱으로? 노코드툴 앱시트로 온보딩 앱 뷰 구성하기

  • 직무 관리(Roll) 및 직원 등록(Self Enrollment) 뷰: primary navigation에 직원 셀프 등록 폼 뷰를 배치하고, 등록 후엔 NOT(IN(USEREMAIL(), employee[email])) 조건으로 뷰를 자동 숨김 처리합니다.
  • 내 프로필(My Profile) 및 전사 인명록 뷰: 로그인 유저 전용 슬라이스 기반 내 프로필 디테일 뷰와 전체 직원을 사번순 정렬한 인명록 덱 뷰(Deck View)를 세팅합니다.
  • 직무별 필수 수강 과목(Required Courses) 자동 매핑: employee 테이블 가상 컬럼에 SELECT(course_list[course_id], CONTAINS([required_roles], [_THISROW].[role])) 수식을 적용해 직무별 수강 과목 리스트를 자동 노출시킵니다.
  • 카테고리별 수강 자료(Documents) 뷰: 전체 자료 리스트를 카테고리별로 그룹핑하여 덱 뷰로 보여주고, 파일 열람/영상 링크 버튼을 배치합니다.
  • 수강 상태별 대시보드(My Courses) 뷰: 트레이닝 슬라이스를 생성해 '진행 필요' 과목과 '진행 완료' 과목을 탭 형태로 분리한 대시보드 뷰를 제작합니다.
  • 가상 컬럼 하이퍼링크(HYPERLINK) 적용: 파일 및 영상 링크 가상 컬럼에 HYPERLINK([file_url], "파일 열람") 수식을 부여하고 Display Name을 공백 처리해 깔끔한 링크 텍스트 UI를 제공합니다.
  • 온보딩 가이드 뷰 및 조건부 스타팅 뷰 세팅: 슬라이드형 온보딩 가이드 뷰를 만들고, IFS(IN(USEREMAIL(), employee[email]), "onboarding_view", TRUE, "self_enrollment_view") 조건식으로 신규/기존 유저의 접속 첫 화면을 다르게 제어합니다.

라벨 종합 정리

  • 앱시트는 데이터 소스(스프레드시트/DB) 설계와 핵심 수식(Ref, LOOKUP, SELECT, CONCATENATE, IFS 등)을 활용해 코딩 없이 강력한 비즈니스 앱을 구축하는 노코드 플랫폼입니다.
  • 유저 권한 및 보안 필터(Security Filter), 슬라이스(Slice), 조건부 뷰(Show_if/Starting View) 세팅을 통해 유저별 맞춤형 인터랙티브 화면과 안정적인 대시보드를 제공할 수 있습니다.
