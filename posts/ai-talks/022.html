헤르메스 멀티에이전트 팀 구축 - Delegate Task vs 칸반 방식 (후츠릿)

영상 정보

  • 영상 URL: https://youtu.be/7XW_O_lS6C4?si=5qs-tY6u7ZGx9iDt
  • 구분: AI창업

요약

[결론] 하나의 에이전트가 리서치부터 글쓰기·배포까지 다 맡는 '가짜 팀'은 매번 비슷한 품질의 결과물과 토큰 낝비를 낳습니다. 해결책은 역할별 전문 프로필(상주 직원)을 따로 두고 공유보드(DB)로 연결하는 '칸반 방식' 멀티에이전트이며, 데스크톱 앱 + 디스코드를 함께 연동해야 실용적입니다.

[핵심 근거]

  1. 기존 방식(Delegate Task)의 한계: 메인 에이전트가 임시 서브 에이전트를 생성·위임하는 방식은 사람 개입 없이 빠르지만, 서브에이전트가 작업 후 사라지며 이전 맥락을 기억하지 못해 매번 일반적인 결과만 내놓으며, 리서치가 잘못되어도 글쓰기/배포까지 끝까지 돌아가 토큰을 낭비합니다.
  2. 칸반 방식의 장점: 각 프로필(리서치/글쓰기/배포 등)이 모두 공유 데이터베이스(보드)를 바라보며 결과물을 저장/열람하는 구조로, 상주하는 독립 직원이라 전문성이 축적되고, 중간에 사람이 개입해 리서치 결과를 검토·반려할 수 있어 불필요한 후속 작업(글쓰기·배포)의 토큰 낙비를 막습니다.
  3. 데스크톱 앱 vs 디스코드 역할 분담: 디스코드는 메시지 800자 제한·긴 답변 분할·스레드 혼잡으로 복잡한 작업에 불리하지만 외출 중 간단한 지시/알림수신에 강하고, 데스크톱 앱은 클로드/코덱스와 동일한 UI로 작업흐름을 직관적으로 볼 수 있어 스킬 생성·자동화 구축에 적합합니다(디스코드 대화로그는 데스크톱 앱에 읽기 전용으로 미러링되지만 역방향은 안 됨).

[구축 절차 요약]

  1. VPS의 기존 헤르메스와 데스크톱 앱을 연동.
  2. 역할별 프로필(샘플: 김비서/소식통/김튜브)을 생성하고 각각 디스코드 봇 토큰을 .env에 등록.
  3. Hermes profile list로 등록 확인 후, 컨테이너 재시작 시 기본적으로 active 프로필의 Gateway만 자동 실행되는 문제를 해결하기 위해 '모든 프로필 Gateway를 자동 실행하는 스크립트'를 헤르메스에 직접 만들게 함.
  4. 스크립트를 한 번 실행한 후 컨테이너를 재시작하면 모든 프로필의 Gateway가 running 상태로 유지됨(이후 재실행 불필요).
  5. 데스크톱 앱에서 프로필을 오가면서 각 전문 직원과 직접 대화, 디스코드에서는 mention으로 특정 팀원을 호출해 협업 진행.

[현재 한계 및 유의사항]

  • default 프로필을 모든 채널의 기본 응답자로 설정해 두면 mention 없이도 계속 답변해 중복 응답이 발생하므로 설정 수정이 필요.
  • 현재 리서치 팀은 일반적인 검색 결과(예: '2026년 키워드는 에이전트형 AI') 위주로 가져와 인사이트가 반복되고 실제 최신 이슈(페이블 5 논란 등)를 놓치므로, 개발자 커뮤니티 반응 기반 트렌드를 가져오는 전용 스킬 개발이 향후 과제로 남아 있음.
  • 현 단계는 팀원들이 서로 직접 협업하는 것이 아니라 사용자와 각각 따로 대화하는 방식으로, 팀간 자동 협업 파이프라인은 후속 영상에서 다룰 예정임.
