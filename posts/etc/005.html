봇을 만드는 봇까지 — 그록봇(Grok Bot) 팀이 AI를 나눠 쓰는 법 (평범한 사업가)

한줄 요약

봇을 몇 개 만드느냐보다 역할을 나누고, 맥락을 넘기고, 사람이 확인할 지점을 정하는 것이 핵심이다. 관찰 → 수정 → 스킬 → 루틴 순서로 자동화를 넓힌다.

챕터별 요약

1. 총괄 비서: 가격 조사부터 판매 글까지 (00:19)

  • 중고 마이크 사진 한 장과 요청 하나로 공식 가격·동네 최저가 조사, 글쓰기 봇에게 예전 판매 글 스타일 문의, 판매 글 게시, 안 팔리면 매주 가격 인하까지 이어짐.
  • 담당자 사이의 맥락 전달이 핵심. 최초 승인과 후속 자동 작업은 구분해서 봐야 함.

2. 이메일·일정, 디자인·글쓰기 봇 (02:55~05:05)

  • 이메일 봇은 오늘 할 일 추출, 일정 봇은 약속 생성·수정. 로그인이 필요하면 사람이 직접 로그인.
  • 메일 읽기·송금·일정 변경은 서로 다른 권한. 글쓰기 봇이 다듬은 초안을 사람이 검토한 뒤 보냄.

3. 기획·디자인·개발 봇의 그룹 대화 / 역할 봇과 프로젝트 대화 (05:05~08:04)

  • 세 봇을 한 그룹 대화에 넣어 아이디어 토론, 특정 봇은 이름을 불러 답을 받음.
  • 봇은 역할·기억·도구를 계속 가져가는 담당자, 프로젝트 대화는 마감이 있는 일. 같은 디자이너 봇이 여러 프로젝트 대화에 참여 가능.

4. 팟캐스트·웹사이트 게시·피그마 (08:04~11:57)

  • 읽던 글 링크를 오디오로 변환.
  • 장소 사진 → 점토 미니어처 이미지(낮·밤 버전) → 배경 제거 → 개인 웹사이트 게시. 저장소의 작업 지침(플레이북)을 따름.
  • 피그마 연결 + 디자인 시스템 스킬로, 사람이 시스템과 첫 화면(약 5%)을 만들고 나머지 흐름을 봇이 확장.

5. 컴퓨터 제어·스킬 평가 (11:57~14:55)

  • 로컬 실행으로 내 컴퓨터의 가상 머신·저장 공간 점검. 조사와 삭제는 나눠서 판단.
  • 스킬을 고칠 때 여러 모델의 에이전트로 시험해 목표 달성이 확인된 경우에만 반영.

6. 닥터 에그봇·생활 비서 (14:55~20:47)

  • 닥터 에그봇은 다른 봇의 역할을 설계. 한 봇에 맥락이 너무 다양하게 쌓이면 대화 기록·루틴을 읽고 역할 분리를 제안.
  • 생활 비서는 여러 도시 항공편·호텔 검색·비교, 예약은 사용자 승인 후. 알림과 결제는 영향이 다름.

7. 개발 팀장 말차와 에이전트 위임 (20:47~24:44)

  • 팀장 봇은 직접 구현하지 않고 나누고 맡기고 감독. 엔지니어 봇이 클라우드 에이전트를 띄워 작업, 난이도에 따라 모델·추론 수준 선택.
  • 큰 프로젝트도 총괄 비서 → 팀장 → 엔지니어 → 실행 에이전트로 전달. 자동 병합은 에이전트 친화적 코드베이스에서의 개인 경험일 뿐, 결과 확인 단계는 필요.

8. 스킬·연결 도구·플러그인 / 소셜 반응 연결 (24:44~28:45)

  • 스킬: 어떻게 할지 적은 재사용 지침. 연결 도구: 외부 앱에서 실제 행동. 플러그인: 둘을 함께 담을 수 있음.
  • 소셜 봇 '포테토'가 30분마다 멘션을 확인하고 같은 버그 신고를 묶어 전달, 팀장 봇이 그 맥락을 바로 가져가 수정안 작성.

9. 일하는 구조 설계와 점진적 자동화 (28:45~끝)

  • 직접 도구 조작 → AI에게 작업 요청 → 역할과 전달 방식 설계로 일하는 방식이 이동.
  • 처음엔 봇이 일하는 걸 관찰하며 고치고, 잘 통하면 스킬로 남기고, 한 번에 잘 될 때 루틴으로 자동화(예: 영수증 메일 → 경비 보고서).
  • 도구·연결·스킬은 공유, 기억·선호는 봇별로 따로. 작은 반복 업무 하나부터 시작.

실무 포인트

  • 봇 숫자보다 역할·맥락 전달·확인 지점을 먼저 정할 것.
  • 검색·비교·초안은 맡기고, 결제·게시·삭제는 사람이 승인.
  • 같은 일을 몇 번 지켜보고 고친 뒤 스킬로 저장, 안정되면 루틴으로.
  • 한 봇에 맥락이 너무 많이 쌓이면 역할을 나눌지 검토.
