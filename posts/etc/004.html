한줄 요약

에이전트를 기존 업무에 끼워 넣지 말고, 에이전트가 믿을 만하게 일할 수 있는 실행 환경을 먼저 만들어라. 누구나 같은 AI를 쓰게 되면 경쟁력은 업무 흐름(2층)과 세계 모델(3층)에서 나온다.

챕터별 요약

1. 기업용 AI 전문 기업, Swit 이주환 대표 (00:33)

  • Swit은 실리콘밸리 본사의 기업 협업·에이전틱 전환(AX) 기업. 이 대표는 새 책 『AI 에이전트 실행 세계』 원리편·설계편(약 1,200쪽)을 출간.
  • 책의 문제의식: 시범 프로젝트 33개 중 실제 프로덕션까지 가는 건 4개뿐. 업무 환경은 그대로 둔 채 LLM API만 붙이는 SI식 접근의 한계.

2. AI 에이전트의 한계와 새로운 환경 설계 (03:44)

  • 회사 없이 직원부터 뽑으면 아무리 똑똑해도 성과를 못 내듯, 에이전트도 실행 환경이 먼저 필요. 기업 스스로 도메인을 에이전트 친화적으로 모델링해야 함.
  • 파괴적 기술은 같은 방식에 끼워지는 것이 아니라 완전히 새로운 환경을 요구함.

3. 언어의 성공과 실행의 성공이 다르다 (08:11)

  • LLM은 확률적으로 언어를 예측하지만 기업 업무(ERP·CRM 등)는 상태 기계. 둘을 잇는 중간 레이어를 모델링하지 않으면 API 연동만으로는 구조적으로 실패.
  • API는 업무 흐름의 작은 스냅샷일 뿐이라 멀티스텝·장기 업무 자동화에는 부족.

4. AI는 똑똑해질수록 믿을 수 없다? (11:48)

  • 모델은 우리 회사의 현실을 모른 채 짐작으로 세계를 만들어 답함. 실제 세계 모델이 없으면 신뢰할 수 없음.
  • 사전학습형 지능과 달리, 환경 속에서 목표 기여도로 평가받는 강화학습형 지속 학습이 있어야 기업 안에서 진화하는 에이전트가 가능.
  • 도구를 쓰는 대화보다 상태를 A에서 B로 바꾸는 실행이 핵심.

5. 업무에 맞춘 AI가 아닌, AI에 맞춘 업무 (14:31)

  • 함수 호출의 연속으로는 사람이 옆에서 지시해야 하는 단타 업무에 그침. 기존 SOP를 에이전트 중심의 상태 기반 워크플로로 바꿔야 밤새·주말에도 안전하게 자율 위임 가능.

6. 언어와 실제 비즈니스는 다르다 (18:26)

  • "언어는 엘리베이터를 타고, 실행은 계단을 탄다." 언어는 층을 건너뛰지만 실행은 상태 전이를 하나도 건너뛸 수 없음.
  • 언어 층위의 실패는 재시도하면 되지만, 비즈니스에서 API 한 번의 실수는 법률·사업 사고가 될 수 있음. 100번, 1,000번 해도 100% 되는 실행 세계를 설계해야 함.

7. 에이전트의 월드를 구축하는 방법, 뉴로심볼릭 (19:48)

  • 신경망은 신호 해석·추정을, 심볼릭(온톨로지·규칙)은 판정·권한·결과 보장을 맡는 분업형 협업.
  • 층위 구분: 레이어 1 에이전트(룰·제약 준수), 레이어 2 워크플로(가드레일), 레이어 3 월드(시뮬레이션 결과와 실제 세계의 괴리 방지). 층위마다 설계 방법과 실패 패턴이 다름.

8. ESTC, 에이전트 월드를 구축하는 지도 (28:17)

  • Entity(개체)·State(상태)·Transition(전이)·Constraint(제약). 예: 운동화 구매 — 고객·상품·결제 개체가 검색→비교→구매→환불 상태로 전이하고, 가능한 전이 경로는 비즈니스 규칙으로 고정.
  • 팔란티어의 온톨로지는 레이어 1(시맨틱 레이어). 레이어 2는 상태·전이로 워크플로 모델링, 레이어 3은 개체 간 제약을 결합한 세계 모델.
  • LLM은 1D, API 스냅샷은 2D, 실제 비즈니스는 시간이 있는 3D. 실행에서 나온 궤적(트래젝터리) 데이터가 기업만의 전략 자산이 됨.

실무 포인트

  • AI 도입 전에 업무를 개체·상태·전이·제약으로 먼저 정리해 볼 것.
  • 되돌릴 수 없는 실행(결제·발송 등)은 확률에 맡기지 말고 규칙과 승인 단계로 고정.
  • 경쟁력은 같은 모델이 아니라 우리 회사의 업무 흐름과 실행 기록에서 나옴.
